# Plugin maintenance

Use the plugin source directory from `codex plugin list --json`. Preserve its absolute path before uninstall; the installed cache may be removed by Codex. Use `scripts/manage.cmd` on Windows or `scripts/manage` on macOS. Add `--json` for structured results. Do not edit Codex configuration, installation caches or management records to simulate success.

- **Status:** run `status`. Report the plugin and actual dependency versions, operation stage and reason for failure. A missing Node runtime is a diagnostic result, not authorization to download. Distinguish dependencies installed, standalone startup check passed, and the two MCPs actually discovered in this task. Check times are historical, not live connection evidence.
- **Diagnostics:** run `doctor` after related tasks stop. This only initializes MCPs and lists tools. Do not run generation, import or scene edits to test installation. Existing processes and conflicting ports require owner diagnosis; never stop them implicitly.
- **Upgrade:** a user request to upgrade the plugin covers the plugin plus both MCPs and automatic cleanup of superseded managed files after success. Show the current versions and scope. Use `upgrade`, or `--scope plugin` / `--scope mcp` when explicitly requested. Local sources require `--source <new-marketplace-root>`; do not substitute a GitHub installation. Keep latest resolution at installation/upgrade time and local reuse on ordinary startup.
- **Failure:** report the failed stage and actual installed state. Offer retry, resuming the old installation if verifiable, or stopping. Run `retry` or `resume-current` only after that choice. After a dependency retry also fails, an explicitly selected exact pair can use `retry --versions <freeform-exact> <lux3d-exact>`. Initialization failures do not unlock alternative-version installation. Never remove failure state or stale locks without inspecting ownership. Report if exact old-source restoration is unavailable. Git restoration can pin the marketplace to the recorded revision; disclose that resulting source.
- **Completion:** report component versions before/after, startup check scope, and cleanup result. Tell the user to restart Codex and open a new task. Verify actual tool discovery there before claiming the current task is connected; browser sign-in and scene readiness remain separate checks.
- **Cleanup:** `cleanup` previews recognized paths and sizes. After the user chooses deletion, run `cleanup --apply`. Successful upgrades perform this automatically and retain only current required resources; busy or unknown resources are deferred. Do not turn a cleanup warning into a failed upgrade or reinstall dependencies.
- **Uninstall:** run `uninstall` only when requested. It preserves external caches and does not remove shared marketplace registrations. Then preview `cleanup --purge-cache`; after the separate deletion choice, use `cleanup --purge-cache --apply`. Explain any retained executing runtime or other deferred resources. Preserve user scenes, source repositories, release archives and unrelated/shared services.

Legacy bootstrap dependency recovery remains supported. It must not bypass a failed unified upgrade. Do not infer business compatibility from a successful initialization or tool list.
